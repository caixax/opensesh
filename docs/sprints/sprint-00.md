## Report

### What was done

- **Repository base:**
  - GPL-3.0-or-later license (verbatim FSF text, [ADR 0001](../adr/0001-license.md)).
  - README and CONTRIBUTING in English only (owner override).
  - `.editorconfig`, `rustfmt.toml`, `clippy.toml`, `.gitattributes` (LF everywhere), `.gitignore`.
  - `rust-toolchain.toml` pinned to the **MSRV 1.88.0** ([ADR 0002](../adr/0002-toolchain-and-msrv.md)).
- **Workspace (edition 2024, resolver 3):**
  - Every third-party version is pinned in `[workspace.dependencies]`, checked on crates.io, and locked by the committed `Cargo.lock`.
  - Workspace lints deny `unwrap_used` / `expect_used` outside tests.
- **`opensesh-core`:**
  - The app identity.
  - The §4.1 directory layout, including portable mode.
  - On Unix, created directories are `0700` and the data directory is kept private.
  - Unit tests.
- **`opensesh-app`** (cxx-qt 0.10, QML module `cc.caixa.opensesh`):
  - A `SesameDoor` Rust QObject whose read-only `knocks`/`open` properties change from a QML button, and an `AppInfo` QML singleton.
  - A small C++ shim for the window icon, the platform name and a Qt message handler, so Qt/QML logs go to `tracing`.
  - `setDesktopFileName("cc.caixa.OpenSesh")`, a `.desktop` file and the placeholder logo.
  - Logging to stderr and to a daily-rotated file.
  - **Crash reporting** ([ADR 0004](../adr/0004-crash-reporting.md)):
    - A panic hook writes a synchronous report and opens a QML crash dialog in a separate process.
    - Only the first panic opens the dialog, and follow-up panics are appended to its report.
    - Qt fatal errors are written as reports too.
  - **Windows release builds:** console attach for `--help`/`--version`, and a message box when startup fails.
  - **`--smoke-test`:**
    - Main window: after the first frame it presses the button three times, checks the Rust object and checks non-ASCII text with an AOT-compiled QML probe.
    - `--crash-report <file> --smoke-test` renders the crash dialog.
- **`xtask`:**
  - `cargo xtask icons`: pinned `lucide-static` 1.48.0, verified by sha256, HTTPS-only with timeouts, byte-reproducible. It also composes the logo and generates `THIRD_PARTY_NOTICES.md` ([ADR 0005](../adr/0005-icon-pipeline-bootstrap.md)).
  - `cargo xtask lint-qml`: hex, named and typed colors, `Qt.rgba` and similar, and strings without `qsTr`, in both `:` bindings and `=` assignments.
- **CI** (`.github/workflows/ci.yml`):
  - fmt, clippy `-D warnings`, tests, QML lint, and an icon reproducibility check that also catches untracked files.
  - cargo-deny and cargo-audit, with pinned versions.
  - Ubuntu 24.04 with aqt Qt, Arch/Fedora/Debian 13 containers, and Windows MSVC, each running both smoke tests.
  - Actions pinned to commit SHAs, cache keys tied to the Qt version, and Dependabot configured.
  - Checked with actionlint.
- **Docs:** `docs/dev-setup.md`, `docs/testing/manual-matrix.md`, [ADR 0003](../adr/0003-qt-version-and-installation.md) (Qt versions and how to get Qt) and `CHANGELOG.md`.

**Multi-agent work:**

- Before implementing, 5 research agents verified crate versions and APIs, GitHub Actions, distro packages and the Lucide source.
- After implementing, an adversarial review ran 6 lenses, and each lens's findings went to a skeptical verifier: 47 findings, **39 confirmed** (none critical or high), 8 rejected.
- All 39 were fixed. The most important:
  - A panic inside a QML → Rust call ran the hook twice (cxx's unwind guard), so the guard's report overwrote the root cause and two dialogs opened.
  - The text-encoding smoke check was a tautology.
  - Qt fatal messages could be lost from the async log.
  - Windows release builds failed silently.

### Decisions and deviations

- **Qt versions** ([ADR 0003](../adr/0003-qt-version-and-installation.md)): 6.10.3 is the reference and 6.8 the minimum. aqtinstall 3.3.0 can't install Qt 6.11+ on Windows yet.
- **Owner overrides:** English only, no push.
- **Fusion is the placeholder Qt Quick Controls style.** The native "Windows" style had unreadable buttons (white on light gray) in the Windows dark theme. Sprint 1 replaces it with the OpenSesh component library.
- **`/utf-8` for MSVC.**
  - The bug: once Fusion's types were known, qmlcachegen compiled bindings to C++, and MSVC read that C++ in the ANSI code page, so "·" rendered as "Â·".
  - The fix: `build.rs` now passes `/utf-8`, as Qt's CMake does.
  - The guard: a typed QML probe that qmlcachegen compiles to C++. Without the flag, the smoke test exits 5.
- **Qt rpath outside the loader's default directories.** `build.rs` embeds an rpath when Qt is not in a default loader directory (aqtinstall, source builds), so `cargo run` works without `LD_LIBRARY_PATH`.
- **Pulled forward from Sprint 1**, in minimal form: the core of the icon pipeline (needed for the placeholder logo without hand-drawn SVG) and the QML lint (required by §10 CI).
- **New dependency:** `windows-sys` 0.61.2, Windows only. It was already in the dependency tree.

### Risks

- **aqtinstall and Qt 6.11+ on Windows.** Moving beyond 6.10.3 depends on an aqtinstall release, or on switching to the online installer.
- **cxx-qt is still 0.x.** Minor versions may break the API, so the C++ shim and the bridges will need updates on bumps.
- **qmlcachegen runs before qmltyperegistrar on clean builds.** Bindings that use our own types fall back to bytecode on a fresh build (the review found this in cxx-qt-build 0.10). This is harmless, but it makes AOT coverage vary between clean and incremental builds.
- **The smoke tests prove that QML loads and the bridge works, not how the app looks.** Visual regressions need the manual matrix until we add screenshot tests.
- **Build noise on Arch:** GCC 16 prints a `-Wsfinae-incomplete` warning from the Qt 6.11 headers. It's harmless.
- **The placeholder logo has low contrast** (white on amber). This is intentional and temporary.
