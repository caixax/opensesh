# ADR 0028: SFTP

- **Status:** accepted
- **Date:** 2026-09-27
- **Sprint:** 8

## Context

PLAN §5.4 asks for the best built-in remote file explorer: a side panel in SSH tabs that follows
the terminal's folder, an SFTP view with two panes, a transfer queue that survives large files
and lost connections, and editing a server's files with the user's editor. The SSH client of
Sprint 7 (ADR 0027) gives connections, prompts and one tokio runtime off the GUI thread.

## Options and decisions

### The library

- Our own SFTP client on `russh` channels: the protocol is small, but pipelining, extensions and
  the many server quirks are not.
- `ssh2` (libssh2): a second SSH stack in C beside `russh`, with its own sessions, host key
  checks and authentication.
- **`russh-sftp` 3.0.0** (Apache-2.0): it runs over any byte stream, so an `sftp` subsystem
  channel of our own connections; reads and writes are pipelined (16 requests in flight); it
  knows the OpenSSH extensions (`statvfs`, `hardlink`, `fsync`, `expand-path`); and its server
  half gives the tests and the smoke test an in-process SFTP server over a temporary folder.

A request that gets no answer fails after 60 s (`request_timeout_secs`), which a lost connection
turns into "disconnected" rather than a hang.

### One interface for both sides

`opensesh-ssh::sftp::Fs` is this computer (`Local`) or a server (`Remote`), with the same
operations: list (links resolved to what they point at, 16 at a time), stat, create, rename,
delete (recursive), chmod, times, symlinks, and reading and writing at an offset. The transfer
engine copies between any two, so local to server, server to local and **server to server**
(through this client) are one code path. Paths are POSIX strings on servers and native on this
computer, where Windows drives sit under an empty root.

### Where connections come from

- **The side panel** of an SSH pane opens a new `sftp` channel on the pane's live connection
  (the backend shares it while it is up): no second login, no second MFA prompt. After a
  reconnection it opens again on the new connection.
- **The SFTP view** connects each side by itself (a saved host or quick-connect text), with the
  same prompt cards as a terminal pane.
- A pane on OpenSSH (the external backend) has no connection to share: its side panel connects
  on its own like the SFTP view.

### The transfer queue

One queue for every window, with the parallel limit of Settings > SFTP (3 by default, up to 16)
shared by all jobs. A job walks its sources, makes the folders, then copies files several at a
time; progress, speed and ETA go to the UI a few times a second.

- **Pause** stops each file after its current chunk and keeps its offset; **resume** continues
  from there, on the same session.
- **A lost connection** fails the job; **retry** takes the panes' new sessions: files already
  there are skipped and partial ones resumed.
- **Files already at the destination:** ask (with "for every file of this transfer"), replace,
  replace if older, continue (resume), skip, or keep both (`name (1).ext`). **Continue** checks
  that the last 64 KiB of the partial file match the source before appending; otherwise the
  file is copied again.
- **Times and permissions** are kept when the settings say so (times by default).
- **A copy within one server** runs `cp -R -p` there over an exec channel, when the destination
  is free and the server has a shell; otherwise the files go through this client.

### Editing a server's file

The file is downloaded into a private folder (the cache's `edit/<id>`, `0700` on Unix; one
sub-folder per edit) and opened with the editor command of Settings > SFTP (`{file}` is the
copy) or the system's application for the file type. A watcher (`notify`, debounced) uploads
each save **after checking that the server's copy still has the time and size it had**; if not,
the user chooses between replacing it, taking the server's copy, or waiting. When the server
refuses the write, **"Save with sudo"** is offered, with a warning: the content goes through
`sudo -S tee`, with the password typed once in the dialog when `sudo -n true` says one is
needed (a password line where none is asked for would end up in the file). The folder is
removed when the edit stops.

### Following the terminal

Shells report their folder with OSC 7, which the terminal already parses; the side panel goes
there when "Follow the terminal" is on. A server's shell that doesn't report it gets an offer:
a few lines for `~/.bashrc` or `~/.zshrc`, shown to copy, and added to the file on the server
**only when the user asks and confirms**, once (a marker line keeps it from being added twice).

### Drag and drop

Files dropped from the file manager are uploaded; files dragged between panes are transferred;
files of this computer can be dragged out to other applications. **Remote files can't be dragged
out:** the drop target wants file URLs when the drag starts, and downloading first would stall
the drag for large files. "Download to…" and dragging to the local pane cover it.

### Servers without SFTP

Rare, but they exist (OpenSSH without `Subsystem sftp`, Dropbear without an sftp-server). The
pane says "This server has no SFTP". [`spikes/scp-fallback`](../../spikes/scp-fallback/README.md)
shows that the SCP protocol over an exec channel works, both ways, but gives no listing, no
resuming and no operations beyond copying; it stays a spike until such servers turn up.

## Consequences

- SFTP needs nothing beyond the SSH connection: no second stack, no second login in SSH tabs.
- Large files are limited by the link and the SSH ciphers, not by the client: 1 GiB went up at
  627 MiB/s and down at 692 MiB/s over the loopback against OpenSSH (release build).
- Remote paths travel as UTF-8; names in other encodings show with replacement characters and
  can't be opened (as in most clients).
- The temporary copies of edited files hold the file's content in clear text on this computer
  while it is being edited (see the [threat model](../threat-model.md)).
- `russh-sftp` 3 is young (released 2026-09-08); its server half is only used by tests.
